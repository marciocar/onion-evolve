## 🏛️ Arquitetura de marca (inegociável)

**Casa de Marca com o Onion como marca-mãe e herói único.** Não é ingredient branding — é o inverso: o **Onion
é a autoridade**; a plataforma (Claude Code) é **metadado de compatibilidade**, do tamanho de uma etiqueta técnica.

1. **Título/H1 = Onion, sempre.** O nome da plataforma NUNCA entra no H1 nem em co-branding de mesmo peso.
   Aparece como badge (shield.io), `<sub>` ou rodapé — nunca como parte do nome do produto.
2. **Léxico de subordinação:** "base atual", "onde a tese se prova primeiro", "o veículo, não a metodologia".
   Nunca "para Claude Code" como se fosse a categoria (soaria plugin/extensão).
3. **Prova de universalidade sempre citada:** "nasceu no Claude Code e foi portado para 6 ferramentas de IA
   para provar exatamente isso" — é **fato verificável** que sustenta a autoridade transcendente, não slogan.
4. **Hierarquia de portas (quartos da mesma casa):** core (privado) → mini (teaser) → **`onion-core` (a porta
   pública viva)** → hub (empresa) → família de 6 ferramentas. Nenhuma porta tem identidade que compita com o Onion.
   ⚠️ **Corrigido em 2026-09-24:** esta linha dizia `standalone (porta pública)`, e isso deixou de ser verdade em
   2026-09-17, quando `onion-core` foi publicada. O `onion-standalone` é **congelado** desde 2026-07-19 — medido,
   412 commits da superfície que viaja atrás do core. Apontar para ele como porta viva manda o público a uma
   versão defasada do framework.

## 🎯 Positioning statement

Para o desenvolvedor (solo ou em time) que orquestra IA no ciclo **produto → engenharia → compliance**, o
**Onion** é o método spec-as-code que transforma decisão perdida no chat em **contexto explícito, versionado e
retomável** — o único framework que trata **compliance/governança como dimensão peer** (não afterthought), prova a
própria disciplina **rodando o artefato de verdade** (dogfood, não claim) e evolui por **federação real** entre
adotantes, não por lista de features. Claude Code é a **base atual**, onde a tese se prova primeiro, não o que a
define — o método já foi portado a 6 ferramentas para demonstrar que **transcende a ferramenta**.

## 💎 Value proposition

Contexto que **não evapora** entre conversas com a IA, disciplina que **não depende de heroísmo** pessoal, e a
única metodologia que trata **compliance como par** de produto e engenharia — provada rodando o próprio artefato.

**Ancoragem factual (o gancho frio, anti-hype):** devs delegam ~60% do trabalho à IA, mas confiam o bastante para
soltar de verdade só em **0–20%** dos casos; o gargalo não é escrever código, é **contexto que se perde entre
sessões** ([Anthropic 2026](https://agentmarketcap.ai/blog/2026/04/05/anthropic-agentic-coding-trends-report-claude-code-eight-shifts)).
Contexto bem mantido: **40% menos erro, 55% mais rápido**. O gap tem preço conhecido — o Onion é o mecanismo que
o ataca versionando o contexto em specs no Git, em vez de deixá-lo evaporar no scroll do chat.

## 🗣️ Brand voice

- **Direto e denso** — sem hand-holding nem enrolação; a densidade vive no conteúdo, não na primeira tela.
- **Técnico e preciso** — léxico nativo (maestro, dogfood, spec-as-code, dimensões peer, federação, adotante,
  SSOT) como termo técnico exato, nunca jargão de hype.
- **Evidência acima de afirmação** — número/mecanismo antes do adjetivo, sempre com fonte citada.
- **Anti-hype-mas-fisga** (a tensão resolvida) — a fisga **não** é superlativo, é a **especificidade do dado
  verificável** ("0–20%", "40%/55%"). O gancho é a precisão, não o volume.
- **Onion é o herói, confiança sem arrogância** — vende rede + prova (verificáveis), nunca "IA mágica".
- **pt-BR** para comunicação/superfície; **inglês** para código, commits e branches.

## 📣 Key messages

1. **Contexto explícito acaba com o heroísmo** — o workflow faseado retomável é o mesmo, toda vez, para qualquer
   dev; você pausa quinta e retoma terça sem reexplicar nada, porque a sessão vive no Git, não na sua memória.
2. **3 dimensões peer é o whitespace, não uma feature** — nenhum concorrente SDD trata produto + engenharia +
   compliance como pares num ciclo só (pesquisa orquestrada 2026-07-12).
3. **O método transcende a ferramenta** — Claude Code é a base atual, não a tese; já portado a 6 ferramentas.
4. **Dogfood é prova, não claim** — um adotante de campo (não o criador) já achou e corrigiu um bug do core
   rodando o Onion de verdade, com commit hash. Confiança verificável.
5. **Grátis é o texto; o moat é a rede que se prova rodando** — o standalone entrega tudo de graça; o que não se
   copia lendo o repo é 3-peer + federação multi-repo + dogfood registrado. É a fronteira comercial inteira.

## 🪜 Messaging por tier

| Tier | Mensagem | Público |
|---|---|---|
| **mini** (teaser) | O "aha" que **não dá pra desver**, **medido**: demo instrumentada no SEU repo, o efeito 40%/55% no seu próprio código — não vídeo, não pitch. Abre com o número, nunca com adjetivo. | prospect frio, baixo compromisso |
| **standalone** (dev solo P5) | A ferramenta **COMPLETA, grátis, para sempre, sem federação**. Não é trial nem versão capada — é moat/advocacy, use tudo. O "aha" aqui é **vivido**: fechar o laptop no meio de `/engineer:work`, rodar `/catch-up` dias depois, a IA retomar citando o `.md` exato. Federação = nota de rodapé ("upsell de time, não seu problema agora"), nunca pegadinha freemium. | dev solo que descobre sozinho, cold |
| **hub** (empresa P3/P4) | O que o standalone **não te dá de propósito**: federação — o método composto entre repos/pessoas, não resetado a cada projeto. O moat que nenhum SDD tem. Para o regulado (P4): compliance-peer vira **trilha de auditoria de IA-no-loop**. | empresa/time que bateu no limite do solo |

## 🏷️ Taglines (ranqueadas — H1/subtítulo é chamada de direção criativa do maestro)

1. **"O que você decidiu ontem, a IA ainda sabe hoje."** — hero/H1 (o momento "não dá pra desver")
2. **"O método que sobra quando a ferramenta muda."** — subtítulo de autoridade (a tese/princípio 1)
3. **"40% menos erro não é promessa — é o que contexto vivo faz (Anthropic, 2026)."** — o gancho anti-hype (prova)
4. "Specs versionadas. Contexto que não evapora." — essência do mecanismo, curta
5. "Não é mais um comando pro Claude Code. É o ciclo inteiro, versionado em Git." — afasta o enquadramento "plugin"
6. "A ferramenta é a base de hoje. O método é seu, sempre." — subordinação da plataforma
7. "Grátis, completo, sem federação: o resto é conversa de empresa, não sua." — promessa do tier standalone

## ✅ Do / ❌ Don't

**FAZER:**
- Onion como único H1 em toda superfície; plataforma sempre badge/subtítulo menor.
- Abrir toda página/porta com **problema → dado mensurável → mecanismo**, antes de qualquer adjetivo.
- Vender o **conceito** (spec-as-code, 3-peer, federação-moat, dogfood); a tabela de comandos vem **depois** da tese.
- Citar a prova de universalidade ("portado a 6 ferramentas") ao reforçar a autoridade sobre a plataforma.
- No frame competitivo, **nomear Agent OS** (rival estrutural mais próximo) + citar a fonte (`competitive-landscape.md`).

**NÃO FAZER:**
- Nunca "Claude Code" no nome/H1 ou em peso igual ao "Onion" (inverteria a arquitetura — princípio 1).
- Nunca abrir com adjetivo hype ("revolucionário", "mágico", "10x") sem o dado que o sustenta.
- Nunca vocabulário de SaaS/pricing (assentos, MRR, "planos") na porta — usar "tier", "bundle", "porta" (D1 não decidido publicamente).
- Nunca prometer federação/rede no standalone (é a fronteira comercial: grátis = sem rede).
- Nunca atacar concorrente por adjetivo sem fonte; nunca listar features como argumento principal.

## 🔒 Aberto — direção criativa do maestro

- **Linha leiga / Onion Pessoal (P6)** — BLOQUEADA por `D3` (tom não-técnico, sem léxico Onion, storytelling de zero).
- **Modelo comercial público (D1)** — "grátis, para sempre" cravado p/ standalone; a mecânica de receita do hub
  (como a federação é precificada/embalada) **não** vira mensagem pública sem decisão (não vazar pricing).
- **Tagline hero definitiva** — #1 ranqueada acima; a escolha final do H1/subtítulo é chamada sua (as top-3 são intercambiáveis).
- **Identidade visual das portas** (mini/hub, além do README standalone) — "quartos da mesma casa" definido; a materialização visual pede o seu olho.
- **design-context como 4ª dimensão peer** — se o gate abrir, revisar o messaging de "3 dimensões peer" (hoje deliberadamente 3).
