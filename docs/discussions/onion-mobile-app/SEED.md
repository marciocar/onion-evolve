# 🧵 App Onion no celular — um Onion de verdade, não o Claude Code

> **Isolada.** Esta linha existe pra pensar, não pra entregar. Nada daqui vai pro core/`main` a menos que o
> maestro peça ("traz isto pro core" / "verifica o que discuti aqui"). Não misturar com os outros temas.

## O tema
Um **app Onion no celular** — uma superfície própria (iOS/Android/PWA), não o Claude Code embarcado. Onde o
Onion (o método: contextos, KG, co-evolução, verticais) vira uma experiência mobile de primeira classe.

## Por que importa pro Onion
- Hoje a plataforma é **única: Claude Code** (decisão de 2026-05-18). Um app mobile é uma **mudança de tese**
  ou uma **superfície da família** (como onion-mini, o site, o a2a) — precisa decidir qual.
- Conecta com o eixo **NS2 (método portátil/destilável, família multi-plataforma)** da north-star.
- O `onion-bridge` (Hono + claude-agent-sdk, PWA) já é meio-caminho: um servidor que serve o core. Um app
  seria o cliente.

## Perguntas de partida
1. É um **cliente do bridge** (o core roda na VPS, o app é janela) ou um Onion **standalone** no device?
2. O que o mobile faz que o desktop não faz — **captura de contexto no mundo** (voz, foto, localização, telas)?
3. Onde entra offline / sync / o KG local? (liga com o tema `behavior-mapping-kg`).
4. Isto fere "plataforma única Claude Code" ou é superfície-de-família (core-vs-família)?

## Conexões com o que já existe
- `onion-bridge` (PWA na VPS), `onion-mini` (destilado público), a doutrina core-vs-família (identidade).
- north-star `NS2` (portátil/família) — `docs/analysis/onion-decision-north-star-2026-07.md`.
