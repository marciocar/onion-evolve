# Sinal — F1 rodou; a doutrina funcionou E rangeu em 3 pontos

O guia do aluno ganhou a camada PLEA (companheiro `ciclo-plea` + costura). As diretrizes 1, 3 e 7
aplicaram limpo. Três fricções reais:

## F-1: "Avaliação forçada" não é forçável em material estático

A diretriz 2 assume um runtime que pode gatear (agente que segura a resposta). Num HTML estático,
o "forçar" degrada para **ritual social** (regra de ouro do squad: "ninguém abre prompt sem
planificação escrita"). Funciona — mas é outra garantia. **Proposta**: a diretriz ganha nuance por
mídia — gate técnico (agente/runtime) · gate estrutural (formulário que trava) · gate ritual
(material estático + combinado de grupo), com o rótulo honesto de cada um.

## F-2: material maduro pede MODO ADITIVO, não reescrita

"Todo artefato educacional com fases embutidas" colide com um guia v2.0 polido e testado:
reescrever é risco sem gatilho. O modo que funcionou: **camada companheira + costura mínima**
(fonte preservada — "adota, não impõe" aplicado a materiais). **Proposta**: a doutrina reconhece
dois modos — nativo (artefato novo já nasce nas fases) e aditivo (artefato existente ganha camada).

## F-3: material de REFERÊNCIA fica fora do escopo das fases

O cartão de prompts é consulta, não jornada — impor PLEA nele seria cerimônia. **Proposta**:
escopo explícito — diretrizes 1-3 valem para materiais de JORNADA/tarefa; materiais de referência
têm só a diretriz 4 (rótulos) e, opcionalmente, ponteiros aos checkpoints.
