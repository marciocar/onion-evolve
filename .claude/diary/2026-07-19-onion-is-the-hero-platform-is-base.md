## Signal
**Onion é a autoridade; a plataforma (Claude Code, ou qualquer base) é a "base atual" — destaque
MENOR, valorizada mas nunca co-título, nunca comprometendo a autoridade do Onion.** Correção do
maestro (2026-07-19, no nascimento da porta pública): o título `🧅 Onion · Standalone (Claude Code)`
foi vetado — o `(Claude Code)` como co-título é **inaceitável em todos os repos e documentações do
Onion**. O Onion é o cara; a plataforma entra como badge/subtítulo leve ("porta para a sua base atual,
Claude Code"), não competindo com a marca no H1.

**E: todo README é oportunidade de VENDER o conceito Onion** — não um cartão funcional. Lidera com
problema→promessa→tese ("a ferramenta é o veículo, não a metodologia; o método vive em specs
versionadas"), não com "o que tem dentro". A cara pública de cada repo é marketing.

## Por que (a régua)
- **Marca:** a tese central do Onion é *universalidade* — o método transcende a ferramenta. Co-brandar
  Onion com UMA plataforma no título contradiz a própria tese (amarraria a marca a uma base). A base é
  intercambiável **por desenho**; então ela é contexto, não co-headline.
- **Venda:** a família é pública e busca adoção (`Q_COLD_ADOPTER` aberto). Um README que só lista
  recursos desperdiça o único momento em que um cold-adopter decide se o conceito vale — o hook é o ativo.

## Como aplicar
- **H1** = Onion (+ sub-brand tipo `· Standalone`). A plataforma NUNCA no H1 como co-título.
- Plataforma = badge discreto (`base-Claude_Code-lightgrey`) + 1 linha de subtítulo. Valoriza a base
  sem elevá-la à autoridade.
- README lidera com o **porquê** (problema→promessa→tese), depois o **quê** (bundle/recursos), depois
  o **como** (começar/adotar).
- Vale para README, docs, case-studies, site — toda superfície pública.
